# Android background assets

PNG masters live in `assets/backgrounds/masters/`, outside the Android source
sets. The APK includes only the generated WebP files under
`app/src/main/res/drawable-nodpi/`. All existing scenes are retained, including
the five Antarctica resources `nora_location_antarctica1` through
`nora_location_antarctica5`. Bermuda and Vatican each add three approved scenes;
all six participate in the existing six-second photo cycle with a 1550 ms
crossfade. Reduced motion uses each region's first image.

| Region | Android resource stems | Approved PNG originals, in cycle order |
| --- | --- | --- |
| Бермуды / BM / 🇧🇲 | `nora_location_bermuda1`–`nora_location_bermuda3` | Бермудский треугольник_ остров и затонувший корабль-1.png; Золотой час над бермудской гаванью-2.png; Бермудское побережье в закатном свете-3.png |
| Ватикан / VA / 🇻🇦 | `nora_location_vatican1`–`nora_location_vatican3` | Ватикан на золотом закате.png; Сикстинская капелла в золотом свете.png; Золотой закат в Ватиканских садах.png |

The approved source PNGs are retained byte-for-byte as renamed masters. Their
native 1672×941 dimensions are preserved in WebP. No newly shipped artwork is
unused. Europe / European Union / EU / Европа / Евросоюз / Европейский союз
resolve explicitly to Европа (EU, 🇪🇺), matching the Windows special-region
label, and use the existing universal scene. A country is never inferred merely
because it lies in Europe.

An explicit Russian or English Bermuda name repairs misleading flag metadata in
the presentation layer. A different country named in the same profile, or an
explicit conflicting ISO token, remains ambiguous. Display correction does not
change the stored profile name, source payload, normalized transport, profile ID,
or subscription linkage.

## Generate and verify

The encoder is pinned to Pillow 11.3.0 with libwebp 1.5.0. The script checks both
versions before encoding so that generated resources can be reproduced exactly.

```sh
python -m pip install -r tools/requirements-background-assets.txt
python tools/background_assets.py build
python tools/background_assets.py verify --reencode
```

`assets/backgrounds/manifest.json` records source and output paths, hashes,
dimensions, byte counts and encoder settings for all 58 resources. Verification
checks the complete inventory, hashes, dimensions and pixel equality for RGBA
images. `--reencode` also checks that regeneration produces identical bytes.

Opaque scenes use WebP quality 95, method 6. Transparent artwork uses lossless
WebP with exact RGBA preservation, including RGB values behind transparent pixels.
The conversion preserves native dimensions, aspect ratios and drawable names;
it does not resize the images. Images remain available offline. Numeric Android
resource IDs may change between builds and must not be stored as profile IDs.

## Compare image quality

```sh
python tools/background_assets.py gallery
python tools/background_assets.py compare --names antarctica1 antarctica2 antarctica3 antarctica4 antarctica5 universe germany3 poland3 --display-size 990 534
```

Comparison images are written to the ignored `build/background-qa/` directory.
The script compares q88, q92 and q95 using native-resolution crops and previews
at the requested physical display dimensions. Inspect sky gradients, snow,
fine details, dark scenes and transparent edges visually; numeric metrics are
additional diagnostics.

The complete PNG master set is 136,584,805 bytes; generated resources total
26,891,144 bytes (80.31% smaller). The six new scenes account for 18,310,654
master bytes and 3,971,164 generated bytes (78.31% smaller). The 52 pre-existing
master/output entries, including Antarctica and transparent artwork, retain their
previous byte counts and SHA-256 hashes. These image-file sizes are separate from APK size, installed
size and decoded bitmap memory. A 1672×941 ARGB frame still needs approximately
6 MiB after decoding.

## Restore PNG resources

To undo image compression, copy each manifest-listed master back into
`drawable-nodpi/` and remove its corresponding WebP. Preserve every resource
stem and never leave both formats with the same stem in the resource directory.
This does not require changes to profiles, subscriptions or transport data.
